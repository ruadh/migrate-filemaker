## Phase 3: Data Migration & Validation

**Goal:** Extract all data from FileMaker and load into Oracle Database with complete validation.

**Effort:** M (Medium)

### Data Migration Plan

#### Extraction Strategy
- Export each FileMaker table to CSV using FileMaker Pro
- Export container fields (photos/documents) as individual files
- Use UTF-8 encoding to preserve special characters
- Document all export parameters for repeatability

#### Transformation Requirements

| Source Table | Target Table | Key Transformations |
|---|---|---|
| **Administration** | `memorial_minutes` | Split name fields, convert dates to Oracle DATE format |
| **Cmte_Membership** | `committee_members` | Map status values to new lookup IDs |
| **Cmte_Milestones** | `milestones` | Validate date formats, map milestone types |
| **Cmte_Correspondence** | `correspondence` | Extract document files, create file references |
| **Cmte_Reference_Documents** | `reference_documents` | Handle document extraction and storage |
| **Email_Templates** | `email_templates` | Direct mapping, validate template syntax |

#### Loading Process
1. **Reference data first**: Load lookup tables (statuses, roles, etc.)
2. **Parent tables**: Load Administration (memorial minutes) records
3. **Child tables**: Load related records (committee members, milestones)
4. **Files**: Upload documents and photos via APEX file management
5. **Validation**: Run integrity checks and data quality reports

#### Validation Criteria
- [ ] Record counts match FileMaker exactly (4,132 total records)
- [ ] All foreign key relationships validate
- [ ] Date fields converted properly (no invalid dates)
- [ ] Text fields preserve formatting and special characters
- [ ] All document files successfully uploaded and accessible
- [ ] Calculated fields produce same results as FileMaker
- [ ] Status values map correctly to new lookup system

### Deliverable
Complete data migration with all 4,132 records validated in Oracle Database.

### Testing
- Data quality report shows 100% success rate
- Spot-check 20 random records per table against FileMaker originals
- All file attachments downloadable via APEX interface
- No orphaned records or broken relationships

## Phase 5: Cutover Execution

**Goal:** Execute the direct cutover from FileMaker to Oracle APEX.

**Effort:** S (Small)

### Cutover Timeline (Weekend Execution)

#### Friday Evening
- [ ] Final data export from FileMaker (capture any new records)
- [ ] Set FileMaker database to read-only mode
- [ ] Notify users of cutover in progress

#### Saturday
- [ ] Load final incremental data to Oracle Database
- [ ] Activate production APEX application
- [ ] Validate all functionality in production environment
- [ ] Test user logins and access permissions
- [ ] Verify all files and documents accessible

#### Sunday
- [ ] Conduct final validation with business users
- [ ] Update any URLs/bookmarks to point to APEX application
- [ ] Send go-live notification to all users
- [ ] Monitor system for first-day issues

### Rollback Plan

**Decision Point:** If critical issues discovered within 24 hours of go-live:

1. **Assess Impact:** Determine if issue prevents daily operations
2. **Rollback Decision:** Made by project sponsor within 4 hours
3. **Rollback Execution:**
   - Reactivate FileMaker database (remove read-only mode)
   - Export any new data entered in APEX during cutover period
   - Import new data back to FileMaker (if any)
   - Notify users of rollback and revised timeline
4. **Issue Resolution:** Fix APEX issues and reschedule cutover

### Success Criteria

- [ ] All users can log in to APEX application
- [ ] All memorial minute records accessible and accurate
- [ ] Document uploads and downloads functional
- [ ] Reports generate correctly
- [ ] No data loss during migration
- [ ] System performance acceptable
- [ ] Users comfortable with new interface

### Deliverable
Live Oracle APEX system replacing FileMaker with all users successfully transitioned.
